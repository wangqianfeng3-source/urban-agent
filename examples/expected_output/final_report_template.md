# 结营小结模板（建议）

> 每人 1-2 页，建议 Day 5 上午完成。写给"营后接手你代码的同学"，不用写成论文。

## 1. 我负责的模块

- 所在组 / 分工；
- 一句话说清你的模块在闭环里的位置（输入是什么、输出是什么、谁消费它）。

## 2. 五天做了什么

- 关键设计选择与**被否掉的备选**（为什么不那样做）；
- 指标/算法/prompt 的最终版定义（维度组附指标定义表；A 组附 prompt 要点）。

## 3. 结果与证据

- 对照任务书 §5 的"做到什么程度算不错"，如实写达成情况；
- 一两张图/表：迭代曲线、校准相关系数、对照小表——从 `runs/` 引用，注明复现命令。

## 4. 弯路与发现

- 至少 1 个走过的弯路或意外发现——这部分往往比结果更有价值；
- 如果做了"高分烂方案"测试：评分器被骗了没有？

## 5. 交接与展望

- 代码入口、测试怎么跑、还欠什么债（TODO / known issues）；
- 如果营后继续做两个月，你会先做什么；是否有意愿参与营后论文。
