# 城市数实空间智能体 —— 5 天训练营任务书

> 2026 AI4CITY 暑期夏令营 · 王东杰（AI 方向）× 刘超（规划方向）
> 版本 v2.0（五天版）· 以下内容均为**建议**，各组可结合实际灵活调整；拿不准时找导师或接口同学聊一句即可。

---

## 1. 我们要做什么

一次真实的城市更新任务是这样开始的：手里有**现有规划方案**（文字与图纸）、**历史数据**（交通、经济、人口）和一组**更新目标**。规划师对这些材料做分析，然后进入漫长的"改方案—核对指标—再改"循环，最后拿出几版方案做比选。慢、依赖个人经验、难以穷尽多种可能。

我们要构建一个**城市更新规划智能体**，把这条流程整体交给机器跑，人只在关键处出手：

1. **输入分析（Phase 0）**：把规划文件与更新需求转译成机器可用的目标配置（`intake.py`）；
2. **智能体循环**：编辑模块**按规划师的思路**修改方案——思路来自**策略卡库**（`strategies.py`，即 urban expert skill：低碳优先、活力优先、绿色宜居、均衡改良、保守渐进…）；评测模块给出质量评价与**下一步怎么改的结构化建议**，回给编辑模块；
3. **Top 5 方案比选**：不同策略卡各自迭代出一版方案，排序后生成**比选报告**（`portfolio.py`），**请规划师从中选择**——选择，而不只是确认。多方案比选本来就是规划实务的标准动作，系统只是把"摆上桌的方案"从两三个变成一桌。

**五天一句话目标：在预置的复兴岛数据上，把两个评估维度（能源与碳、人和社会）和策略卡库做实、让 LLM 编辑器跑起来，结营时演示"输入一句更新需求 → 系统产出 Top 5 方案比选报告 → 规划师选择后继续人机共创"。**

> 为什么只做两个维度？五天里"做深"比"铺广"更有价值。能源与碳（刘超老师组有现成杨浦碳核算基础）和人和社会（PPT 第 25 页已有六维评分雏形）是最有抓手的两维；公共服务、交通、历史文化等其余维度只预留接口，营后按同一模板接入。

好消息：你们不是从零开始——这条流程的骨架**已经端到端能跑**：22 个测试全绿；`python -m urban_agent.compare` 一条命令产出真实的五策略比选报告；工作台四个标签页（人工编辑 / AI 建议·人拍板 / Top 5 比选 / 历史报告）全部可操作。五天的任务是把骨架里的玩具零件换成真的。

### 建议做 / 建议留给营后

| 五天内做 | 营后再做（写进未来工作） |
|---|---|
| 预置复兴岛数据（行前备好，营内直接用） | 营内现场清洗原始数据 |
| 文本需求 → 目标配置（关键词版已内置，营内升级为 LLM 结构化抽取） | 完整规划文本库自动解析 |
| 图纸**行前人工转译**成地块数据；营内只做多模态 LLM 读图小探索 | 图纸自动识别（独立研究课题，诚实不承诺） |
| 策略卡库：内置 5 张，规划轨每人再写 1-2 张 | 策略库体系化、接真实案例库 |
| 能源与碳、人和社会 2 个维度做深，每维 3-4 条真指标 | 8 维全覆盖、完整指标表 |
| LLM 编辑器（function calling + 策略注入）+ 与规则式基线对比 | prompt 深度调优、模型微调 |
| Top 5 方案比选报告在真数据上重跑 | 比选报告加成本测算、实施时序 |
| 小型校准（8-10 个变体、2-4 位规划背景师生盲评） | 正式专家校准实验 |

## 2. 系统架构与仓库对应

```
输入：现有方案（文字/图纸）+ 历史数据 + 更新目标
      │
      ▼  Phase 0 输入分析 intake.py（需求 → 目标配置/候选策略）
      │
      ▼        ┌── 策略卡库 strategies.py（urban expert skill）
┌─ 智能体循环 loop.py ──┴──────────────────────────┐
│                                                  │
│   编辑模块 editor.py ──受限动作──▶ 方案 schema.py │
│   （按策略卡思路修改） actions.py        │        │
│        ▲                                ▼        │
│   结构化反馈 ◀──────── 评估模块 evaluators/       │
│  （违规+下一步建议）   硬约束 check_hard()        │
│                        软评分 score_soft()       │
└──────────────────┬───────────────────────────────┘
                   ▼  每张策略卡一条轨迹
     Top 5 方案比选 portfolio.py → 比选报告 → 规划师选择
                   ▼
     交互工作台 app/ → 载入所选方案，继续人机共创
```

五条**设计建议**（骨架已经这么做了，建议沿用；想偏离时先和接口同学聊一句，避免别的组跟着返工）：

1. 编辑尽量走 `actions.py` 的动作空间，不直接改 Plan 字段——这是"可解释、可回滚"的来源；
2. 评估反馈尽量机器可执行：硬违规带 `fix` 动作、软建议是动作字典——这是闭环能收敛的前提；
3. 任一硬违规 → 综合分归零（一票否决）——"按规矩来"优先于"分数好看"；
4. 规划师的思路写成**策略卡**进库，不散落在 prompt 里——策略即数据，可比选、可复用、可署名；
5. Schema 与评估器接口五天内尽量保持现状——只有五天，接口一动全组联动，性价比通常不高。

## 3. 分组建议（12 人版）

| 组 | 人数 | 背景建议 | 主战场 |
|---|---|---|---|
| A 平台与智能体 | 3 | 偏 CS，会 Python | `editor.py` `llm.py` `loop.py` `intake.py` |
| B 数据与 GIS | 2 | 偏 GIS/规划信息化 | `data/` 空间计算函数、图纸转译 |
| C1 能源与碳 | 3（2 技术 + 1 规划） | 有碳核算基础更好 | `evaluators/carbon.py` + 碳策略卡 |
| C2 人和社会 | 3（2 技术 + 1 规划） | 熟悉街道设计导则更好 | `evaluators/society.py` + 活力策略卡 |
| D 交互工作台 | 1（A 组 1 人搭手） | 会 Streamlit/前端更好 | `app/streamlit_app.py`（含比选页） |

两个维度只有两组，所以做得更深：每组除评估器外还负责本维度的策略卡与本维度的校准。

**10 人版**：C1、C2 各 2 人（1 规划 + 1 技术），其余不变。

建议 A、B 组各出 1 人兼任"接口同学"（分别看护评估器接口和 Plan Schema），谁想改接口先找他们聊，不是审批，是让消息传得快。

**规划轨的共同任务（跨组）**：`strategies.py` 里的**策略卡库**由各维度组的规划背景同学共同扩建——每人认领并撰写 1-2 张新卡（如 TOD 导向、历史风貌友好、职住平衡、渐进式微更新），格式照抄内置的 5 张。策略卡会被比选系统实际调用，结营的 Top 5 报告里每张卡都有署名。

## 4. 五天节奏（建议）

### Day 0 · 行前（价值最高的一天，虽然它不算营期）

- **导师侧**：预置复兴岛地块数据（GeoJSON，直接可被 `Plan.from_geojson()` 加载）、LLM API key、仓库权限。**五天营期没有留数据清洗时间，行前数据完成度直接决定营期上限。**
- **学生侧**：按 [预习材料](预习材料.md) 跑通环境和 demo、完成分轨小练习。行前多花 1 小时 ≈ 营期省 1 天。

### Day 1 · 上手与认领

- 上午：项目讲解（立项 PPT + 骨架 walkthrough + 交互工作台演示，含 Top 5 比选页）；分组认领。
- 下午：各组进入主战场——
  - A：换真 key 跑 `--editor llm`，观察动作合法率与收敛情况；试跑 `python -m urban_agent.compare`；
  - B：预置数据加载验证 + 在工作台地图上肉眼检查；
  - C1-C2：从本文档 §6 的起步指标里挑 2-3 条硬约束 + 2-3 条软指标，确定阈值出处；**规划背景同学同时认领各自的策略卡选题**；
  - D：把工作台四个标签页跑熟，列现场演示需求清单。
- 晚：全体 30 分钟同步。**若 schema 真有非改不可的字段，今晚定，明早改完。**

### Day 2 · 各模块做实

- A：prompt 迭代（把评估反馈用好）+ LLM 策略注入调优；`intake.py` 需求解析从关键词版升级为 LLM 结构化抽取；
- B：把 2 个空间函数做真（路网/直线可达性、混合度），供 C 组调用；
- C1-C2：`check_hard()` 用真阈值落地 + `score_soft()` 接真数据；**规划轨：策略卡初稿入库，跑一遍比选看效果**；
- D：按 Day 1 需求清单完善工作台（现场要演示的每个交互都过一遍）。
- 晚同步：明天是集成日，今晚把各自的接口对齐。

### Day 3 · 集成日（本周最关键的一天）

- 上午：两个真评估器接入闭环，端到端在预置数据上跑通——**这是全营的里程碑**；
- 下午：修集成 bug；**用全量策略卡（内置 5 张 + 营期新增）首跑真数据 Top 5 比选**；比选产出的方案变体正好供明天校准使用；
- D + A：工作台接入真实闭环，"需求输入 → 比选 → 选择 → 继续共创"演示流程串一遍。

### Day 4 · 实验与打磨

- 上午：**小型校准**——2-4 位规划背景师生对比选产出的方案盲评（各维 1-5 分），与 AI 评分算 Spearman 相关。对得上是成果，对不上分析原因也是成果；
- 下午：LLM vs 规则式对照数据跑齐；每组试构造 1 个"高分烂方案"考验评分器；**Top 5 比选报告定稿**；demo 彩排第一遍；
- 晚：汇总结果，开始拼结营 slides。

### Day 5 · 收官

- 上午：每人 1-2 页小结（模板见 `examples/expected_output/final_report_template.md`）；demo 最终彩排；
- 下午：**结营答辩 + 现场交互演示**（建议让观众上手点一轮"AI 建议 → 人拍板"）；复盘 + 营后 roadmap（真数据全量接入、8 维扩展、论文分工）。

## 5. 各组的"做到什么程度算不错"（参考，不是验收）

- **A**：LLM 编辑器在两个评估器下大多数运行能在 8 轮内达标；策略注入后不同卡的行为肉眼可辨；需求解析 LLM 版能把一段真实规划文本转成目标配置；有一张 LLM vs 规则式的对照小表。
- **B**：预置数据一行代码直载；≥2 个真实空间指标函数带测试；数据来源可追溯。
- **C1-C2**：每维 ≥2 条真硬约束 + ≥2 条真软指标；违规尽量都带可执行 `fix`；校准实验里自己维度的相关系数算出来了（高低都行，能解释就好）。
- **规划轨（跨组）**：策略卡库 ≥8 张（内置 5 + 新增 ≥3），每张都被比选系统实际跑过，比选报告里能看出不同卡的方案差异。
- **D**：结营现场，一位没看过代码的规划背景观众能自己操作"输入需求 → 生成比选 → 选择方案 → 改方案 → 让 AI 提建议 → 拍板"一整轮。

## 6. 各维度起步指标（Day 1 挑选用）

- **C1 能源与碳**：硬——零碳区禁工业、零碳区容积率上限、绿建达标；软——分部门碳核算（接刘超老师组现有方法）相对基准的减排率。
- **C2 人和社会**：硬——居住绿地率下限、无障碍通达（立项 PPT 第 25 页的一票否决项）；软——功能混合度、Citywalk 友好度（高宽比+遮荫的简化版）、设施多样性。
（公共服务、交通出行等其余维度本期只预留接口，不做实——见 §1 的"为什么只做两个维度"。）

**策略卡起步库**（`strategies.py` 已内置，营期新增候选选题）：已有——低碳优先、活力优先、绿色宜居、均衡改良、保守渐进；候选——增汇固碳（绿地/碳汇最大化）、历史风貌友好（保护优先的更新时序）、紧凑高活力（提高强度换混合活力）、渐进式微更新（分期实施导向）。候选卡都只用能源与碳 + 人和社会两维打分，营内可直接跑比选看效果。

## 8. 风险与退路

| 风险 | 建议对策 |
|---|---|
| 预置数据行前没备齐 | 玩具数据完整可用，全部开发照常进行，Day 3 前随时热替换 |
| LLM 编辑器不收敛 | 规则式 MockEditor 是保底演示路径；"LLM 何时失败"本身就是有价值的观察 |
| 校准对不上（相关低） | 不是失败——分析分歧样本，是答辩里最有意思的部分 |
| 某维度进度落后 | 闭环 ≥2 个评估器即可演示；落后维度降级为"指标文档 + 接口占位" |
| Top 5 方案同质化（比选没差异） | 策略卡加大动作倾向差异；诚实呈现"本片区各策略殊途同归"也是结论 |
| Day 3 集成撞车 | Day 1 晚把接口疑问清零；Day 2 晚提前对齐；有骨架在，撞车面积有限 |

**兜底**：即使 LLM 线全不顺，"两维度评估工具箱 + 策略卡库 + Top 5 比选报告 + 交互工作台"也足够支撑一场漂亮的结营答辩。
